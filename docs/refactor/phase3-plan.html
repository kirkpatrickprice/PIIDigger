Locked TOML format (2.0)

Snake_case throughout. Every list field is always a list — no bare strings. OS sub-tables kept for start_dirs and exclude_dirs so one config file works across platforms. from_toml() selects the current-OS sub-table and exposes flat resolved fields.

# piidigger.toml — 2.0 format

data_handlers           = ["pan", "email"]
local_files_only        = true
max_workers             = 4          # optional; defaults to cpu_count()
default_timeout_seconds = 30         # optional

[include_files]
ext  = ["all"]    # always a list; ["all"] = all supported extensions
mime = ["all"]    # always a list; ["all"] = all supported MIME types

[include_files.start_dirs]
windows = ["all"]   # always a list; ["all"] = all drive letters
linux   = ["/"]
darwin  = ["/"]

[exclude_dirs]
windows = ["C:\\Windows", "C:\\Program Files (x86)", "C:\\Program Files"]
linux   = ["/boot", "/dev", "/etc", "/proc", "/run", "/snap", "/sys",
           "/usr/bin", "/usr/lib", "/usr/local", "/usr/sbin", "/usr/share"]
darwin  = ["/dev", "/etc", "/usr/bin", "/usr/local/Homebrew",
           "/usr/lib", "/usr/sbin", "/Applications", "/System"]

[results]
path = "piidigger-results/"
csv  = true
json = true
text = true

[logging]
log_level = "WARNING"
log_file  = "logs/piidigger.log"

Resolved Config model shape

from_toml() does the OS-selection and expansion internally. The Config object exposed to the rest of the codebase is always flat — no OS nesting, no "all" sentinels.

class Config(BaseModel):
    # Resolved from include_files.start_dirs.<current_os> + "all" expansion
    start_dirs: list[Path]        # never empty after validation

    # Resolved from exclude_dirs.<current_os>
    exclude_dirs: list[str]       # linux and darwin are distinct sets

    # Resolved from include_files; "all" expanded to concrete values
    include_exts: list[str]       # e.g. [".txt", ".pdf", ".docx", ...]
    include_mime: list[str]       # [] if python-magic not installed

    # Resolved from data_handlers list; "all" expands to all registry names
    data_handlers: list[str]      # unknown names rejected at load time

    # Direct fields
    local_files_only: bool = True
    max_workers: int              # default: cpu_count()
    default_timeout_seconds: int = 30

    # Flattened from [logging] section
    log_file: Path                # default: Path("logs/piidigger.log")
    log_level: str                # default: "WARNING"

    # Nested
    results: ResultsConfig        # path, csv, json_, text booleans

from_toml() loading sequence

  • Read raw TOML dict; fail fast on TOMLDecodeError with clear message
  • Detect OS via platform.system().lower() → "windows" / "linux" / "darwin"
  • Extract include_files.start_dirs[os] → validate each path exists, or expand "all" to system roots
  • Extract exclude_dirs[os] → keep as-is (no existence check; missing dirs silently skipped at scan time)
  • Expand include_files.ext/mime/data_handlers if ["all"]
  • Construct and return validated Config
Invariant from "always a list" rule: validators never accept a bare string for ext, mime, start_dirs, or data_handlers. If someone writes ext = "all" in the TOML, Pydantic raises a clear validation error pointing to the field — not a cryptic runtime crash.

CsvSink (csv.py)

  • open(): create output file; write CSV header (source_path, handler, match_type, value)
  • write(record: ResultRecord): flatten record.matches — one CSV row per individual match value
  • close(): flush and close the file writer

JsonSink (json.py)

  • One json = true config flag produces two paired files with the same timestamp: hostname-TIMESTAMP.jsonl and hostname-TIMESTAMP.json
  • open(): open the .jsonl file for writing
  • write(record: ResultRecord): jsonl_file.write(record.model_dump_json() + "\n") — streams one line per record, no memory accumulation
  • close(): flush and close the .jsonl file, then read it back line-by-line and write the .json file as a standard JSON array. Runs inside the coordinator's finally block, so both files are produced on normal exit and on Ctrl+C. Only a hard kill (kill -9) bypasses finally; in that scenario the .jsonl partial file remains valid.

  • Maintains current YAML-like format (file is called "text" but written as YAML)
  • open() / write(record)) / close() per pattern above

E1
Real handle_enum_dir + handle_scan_file
src/piidigger/orchestration/worker.py
Core logic Strict mypy required

handle_enum_dir

  • Parse payload: EnumDirPayload.model_validate(task.payload)
  • Use os.scandir() to list entries (faster than Path.iterdir())
  • For each subdirectory:
    • Skip if name matches any pattern in ctx.config.exclude_dirs
    • Skip if ctx.config.local_files_only and it's a network/removable drive
    • Else: emit one Task(ENUM_DIR, EnumDirPayload(path=..., depth=depth+1))
  • For each file:
    • Get extension; check against ctx.config.include_exts
    • MIME check only if extension matches and MIME list is non-empty
    • If matched: emit one Task(SCAN_FILE, ScanFilePayload(...))
  • Handle PermissionError, OSError, FileNotFoundError — log + continue, don't fail the task
  • Return: new_tasks (serialised task dicts) + counters: {"dirs_scanned": 1, "dirs_found": N, "files_found": M}

handle_scan_file

  • Parse payload: ScanFilePayload.model_validate(task.payload)
  • Construct FilesystemItem(Path(payload.file_path))
  • Look up FileHandler via get_file_handler(item.ext, item.mime)
  • If no handler: log at DEBUG and return status="ok" with empty findings
  • Iterate chunks from file_handler.read(item)
  • For each chunk, call every enabled DataHandler.find_matches(chunk)
  • If a handler returns matches: build ResultRecord(source_path=item.display_path, handler=handler.name, matches=...)
  • Return findings as [record.model_dump() for record in records] and counters: {"files_scanned": 1, "bytes_scanned": item.size}
  • Handle unreadable files, encoding errors with status="error"

def run_scan(config: Config) -> int:
    log_queue: mp.Queue = mp.Queue()
    task_queue: mp.Queue = mp.Queue()
    result_queue: mp.Queue = mp.Queue()
    stop_event = mp.Event()

    ctx = WorkerContext(config=config, task_queue=task_queue,
                        result_queue=result_queue, log_queue=log_queue,
                        stop_event=stop_event)

    listener = start_listener(log_queue, config.log_file, config.log_level)
    workers = start_worker_pool(ctx, config.max_workers)
    sinks = get_enabled_sinks(config)
    for sink in sinks:
        sink.open()

    progress = ProgressDisplay()
    progress.start()

    try:
        run_coordinator(ctx, workers, listener, sinks, progress)
        return 0
    except Exception:
        return 1

Risks & Mitigations

⚠️
Existing tests break on handler interface rename
test_email.py, test_pan.py, and all file handler tests use the old module-level function signatures. They will fail until updated.
Mitigation: update tests in the same commit as the handler changes. This is mechanical — same assertions, new call sites.
⚠️
mypy --strict on orchestration/ including new handler code
handle_enum_dir and handle_scan_file are in orchestration/worker.py which is held to mypy --strict. All return types and exception paths must be fully annotated.
Mitigation: annotate as you write; run mypy after each handler to catch issues early.
⚠️
Config start_dirs normalization on Windows
The 1.x code expands "all" to all drive letters via string.ascii_uppercase + os.path.exists(d + ":"). This logic must be ported correctly to the Pydantic validator; if it runs at import time it may interact with test fixtures.
Mitigation: put "all" expansion in a model_validator(mode="after"), not in __init__. The memory note about this normalization is tracked.
⚠️
Coordinator _route_to_sinks needs dict→ResultRecord conversion
Currently calls sink.write(finding) where finding is a dict. The new OutputSink.write takes a ResultRecord. This requires a 2-line change to coordinator.py — a Phase 2 file.
Mitigation: small targeted change; already identified. Not a re-architecture — just add ResultRecord.model_validate(finding) at the call site.
⚠️
xlsx/xls handlers require materialize() — creates temp copies of PII
openpyxl and xlrd require a real file path. For Phase 3 (on-disk files), materialize() just returns the path itself — no temp copy. This only becomes a security concern in Phase 5 (archives). Nevertheless, the reason should be documented in the method.
Mitigation: add a docstring note in xlsx.py and xls.py explaining why materialize() is called and that for FilesystemItem it returns the path itself (no copy).
ℹ️
Phase 0 tasks are still incomplete
snake_case renames across datahandlers/, filehandlers/, outputhandlers/ are technically Phase 0 work. Phase 3 will complete this as part of the class restructuring.
Mitigation: the Phase 3 handler re-contracting naturally performs the Phase 0 renames. No separate Phase 0 commit needed — just note in the PR that Phase 0 naming tasks are being closed by Phase 3.
